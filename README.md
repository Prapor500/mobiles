# DriveNext — лабораторная работа №1

Проект реализует лабораторную работу №1 из методички «Разработка мобильных приложений».

## Что реализовано

1. Системный SplashScreen через AndroidX `core-splashscreen`.
2. Экран «Экран загрузки» DriveNext, отображаемый 2,5 секунды.
3. Проверка подключения через `ConnectivityManager`, `activeNetwork`, `getNetworkCapabilities()` и `NET_CAPABILITY_INTERNET`/`NET_CAPABILITY_VALIDATED`.
4. Экран «Нет подключения к интернету».
5. Кнопка «Повторить попытку» с индикатором выполнения.
6. Onboarding из трёх слайдов через `ViewPager2` и `FragmentStateAdapter`.
7. Кнопки «Пропустить», «Далее» и «Поехали».
8. Сохранение факта прохождения onboarding через `SharedPreferences`.
9. Clean Architecture: data / domain / presentation / ui.
10. Отдельный `MainViewModel`; переходы выполняются через состояние ViewModel.
11. Адаптивная XML-верстка без фиксированной ширины экрана.
12. Manifest permissions `INTERNET` и `ACCESS_NETWORK_STATE`.
13. Заглушки экранов Login/Main, чтобы переходы лабораторной можно было демонстрировать целиком.

## Важное замечание по методичке

В методичке есть противоречие: в описании SplashScreen сказано, что при первом открытии после загрузки нужно перейти к экрану входа, но раздел «Экран Приветствия» отдельно требует показывать onboarding именно при первом открытии и сохранять факт его прохождения. Для лабораторной реализован логичный вариант: первый запуск -> Splash -> проверка интернета -> onboarding -> Login; следующие запуски -> Splash -> Login, если нет access token. Это позволяет фактически проверить требуемый в ЛР1 ViewPager2 и сохранение состояния onboarding.

- Android 16 / API 36

SDK Tools:

- Android SDK Build-Tools 36.0.0
- Android SDK Platform-Tools
- Android Emulator

Для запуска эмулятора создать устройство Phone. Для основной демонстрации можно использовать system image API 36. Для проверки минимальной версии создать второй эмулятор API 31.

## Запуск

1. Открыть каталог проекта в Android Studio.
2. Дождаться синхронизации Gradle и загрузки зависимостей.
3. Создать Android Virtual Device в Device Manager.
4. Запустить эмулятор.
5. Запустить конфигурацию `app` через Run.

Если Android Studio предложит выбрать Gradle, использовать Gradle 9.6.0.

## Проверка лабораторной

### Сценарий 1 — первый запуск с интернетом

1. Очистить данные приложения или удалить его.
2. Убедиться, что у эмулятора есть интернет.
3. Запустить приложение.
4. Появится экран загрузки.
5. Через примерно 2,5 секунды откроется onboarding.
6. Нажать «Далее» два раза.
7. На третьем слайде должна появиться кнопка «Поехали».
8. Нажать «Поехали».
9. Откроется экран Login.

### Сценарий 2 — пропуск onboarding

1. Очистить данные приложения.
2. Запустить приложение с интернетом.
3. На onboarding нажать «Пропустить».
4. Должен открыться Login.
5. Перезапустить приложение.
6. Onboarding больше не должен появляться.

### Сценарий 3 — отсутствие интернета

1. Очистить данные приложения.
2. Отключить интернет у эмулятора.
3. Запустить приложение.
4. После Splash должен появиться экран «Нет подключения к интернету».
5. Кнопка «Повторить попытку» доступна.
6. Включить интернет.
7. Нажать «Повторить попытку».
8. После успешной проверки приложение продолжит сценарий.

### Сценарий 4 — повторная ошибка

1. Открыть экран No Connection.
2. Оставить интернет выключенным.
3. Нажать «Повторить попытку».
4. На время проверки появляется loader.
5. После проверки экран No Connection остаётся активным.

## Структура проекта

`data` — работа с сетью и локальными настройками.

`domain` — use case для проверки интернета и работы с состоянием onboarding.

`presentation` — `MainViewModel` и состояние запуска приложения.

`ui` — Activity и Fragment-экраны, включая ViewPager2 onboarding.

## Контрольные вопросы

1. Переменная в Kotlin создаётся через `var` или `val`. `var` можно переопределять, `val` — нельзя после инициализации.

2. Activity — компонент Android, который представляет отдельный экран и участвует в жизненном цикле пользовательского интерфейса.

3. Intent — объект сообщения, используемый для запуска Activity и других компонентов Android и передачи данных между ними.

4. SplashScreen — стартовый экран, который показывается во время запуска и инициализации приложения. Он скрывает задержку запуска и предотвращает визуальные артефакты до готовности основного интерфейса.

5. Тема SplashScreen указывается в ресурсах темы приложения и назначается стартовой Activity через AndroidManifest.xml. В проекте это `Theme.DriveNext.Starting`.

6. Инициализация выполняется в `onCreate()` стартовой Activity и должна быть вызвана до установки основного UI, чтобы системный SplashScreen корректно связался с жизненным циклом Activity.

7. `uses-permission` объявляются в `AndroidManifest.xml` на уровне `<manifest>`. Если требуемого разрешения нет, приложение не получит соответствующий доступ; для ряда операций это приведёт к ошибке или невозможности выполнить действие.

8. `INTERNET` разрешает приложению выполнять сетевые запросы. `ACCESS_NETWORK_STATE` разрешает получать сведения о состоянии сетевого подключения через системные сетевые API.

9. `AndroidManifest.xml` — основной конфигурационный файл Android-приложения. В нём описываются компоненты, точки входа, разрешения и параметры приложения.

10. Fragment — часть пользовательского интерфейса, которая обычно размещается внутри Activity и имеет собственный жизненный цикл. Activity является полноценным Android-компонентом и может быть точкой запуска экрана; Fragment сам по себе не является отдельной точкой запуска приложения.
